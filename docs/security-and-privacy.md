# Security and privacy boundaries

Repository source and telemetry are untrusted. The scanner uses Python AST, never executes imports and never reads `.env` values. It excludes virtual environments, generated/binary directories, root gitignore matches, symlink escapes and oversized source/config files. Output includes source references and redacted model expressions; prompt literals remain absent. Maliciously constructed AST depth and syntax failures are reported. Full adversarial sandboxing of parser CPU on massive repositories remains future hardening.

Metadata events have an allowlisted Pydantic schema with unknown fields forbidden. No arbitrary span attributes, raw provider response, error message, request header, provider request ID, raw user ID, payload pointer or prompt/response is accepted. Content capture is unavailable even when requested; initialization refuses it. Token values, credentials and provider exception messages are not logged by Cutback. User-defined identifier values must still be nonsensitive; a malicious sender can encode private information in an allowed metadata value. Metadata itself requires customer authorization.

Ingestion associates a project/environment using the hashed scoped key, then checks payload scope. Bootstrap admin cannot use the ingest endpoint; application ingestion keys cannot read reports. Viewer keys cannot mint credentials or cross projects. Key issuance/revocation and project creation are audited without key material. Key values are returned only on creation and CLI administration saves them to exclusive private files. API validation errors are generic and never echo request bodies. SQL parameters are hidden from engine diagnostics. Application access logs are disabled by default.

The exporter performs network I/O on its daemon worker only. Queue, batch, body size, timeouts and retry count are bounded. Failed export drops telemetry with counters, while provider behavior is unchanged. Endpoint TLS checks, no redirects, and no implicit environment proxies reduce accidental key exfiltration. A configured endpoint is still a trusted customer destination; Cutback cannot verify that the customer's authorized server handles data correctly.

The collector caps JSON bodies to 1 MiB, batches to 200 events, timestamp skew to 5 minutes future/30 days past, read periods to 395 days, and paginated event lists to 100 records. Unauthorized or invalid batches persist nothing. Quotas are local process windows; a public multi-replica gateway needs shared limits. Metrics require admin auth. Liveness discloses only service status. Operational logs/counters are not a compliance audit system.

Open gaps: default retention/deletion worker, remote health aggregation, distributed quotas, SSO/RBAC users, protected optional object storage, encrypted export/restore verification, independent threat testing and complete supply-chain release gates. These prevent treating the development stack as production ready. No the pilot application credentials, runtime data or infrastructure have been accessed.

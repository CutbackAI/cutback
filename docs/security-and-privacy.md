# Security and privacy

Public product examples use generic synthetic applications. Keep private application source, identifiers, paths, reports and deployment plans in the application's own ignored workspace; they are not Cutback publication inputs. Private publication marker policies stay outside the repository. `scripts/check_public_boundary.py` checks current files, Git history and release archives without logging marker values; CI checks tracked publication files and built distributions. Review media and sharing scope separately before publishing customer-derived material. See [independent application onboarding](application-onboarding.md).

Source, telemetry, samples and provider outputs are untrusted. The scanner parses without executing application code, excludes secrets/binaries and bounds size/count/depth/time. Default output contains references, not prompt content.

The collector authenticates scope, validates schema/body/time/environment, rejects content in metadata, hashes/expires/revokes keys, shares quotas and acknowledges after persistence. Ingest cannot read; viewers cannot alter policy/budget. Errors never echo validation input or sensitive traces. Bootstrap admin, DB privileges, secrets, network and backup operators are separate boundaries.

Capture is denied by default at SDK/server. Active approved policy and encrypted storage are required. Samples are scoped, sampled, bounded and redacted before transport. Inputs/references/labels and prompt/rubric variants remain encrypted separately; purpose-scoped admin content reads are audited. Redaction is incomplete, so data-owner authorization remains necessary.

No implicit paid model, production tool execution, hosted account or corporate endpoint exists. Runtime provider keys never enter the browser. Budget approval freezes a dataset/plan/evaluator/rate contract for one run. Reservations precede calls and survive uncertain billing. Payload instructions cannot trigger agent actions; judges return constrained votes and do not independently establish correctness.

Browser credentials live only in memory and clear on disconnect. Same-origin authenticated requests, escaped rendering, CSP/frame denial/no-referrer/no-store and exact proxy trust support defense in depth. Enterprise identity is later scope.

Residual risks include host/key compromise, incomplete redaction, unsupported evaluator/provider behavior, unknown traffic coverage, storage/DB failure reconciliation, backup/version erasure and real cloud lifecycle behavior. Use isolated staging and customer IAM/network/lifecycle/restore monitoring. No security certification, legal compliance, penetration-test or production readiness claim is made.

Lockfiles, pinned actions, dependency audits/license inventory, CodeQL, release archive exclusions and trusted-publisher provenance support supply-chain review. Audits are dated evidence, not guarantees against unknown vulnerabilities. Report privately through SECURITY.md.

# What works and what remains

The working-source [stage runner](agent-workflow.md) adds one `workflow run`
command for an already approved native/cache/context/retrieval or routing stage.
It can wait for a remote worker using an HTTP-only installation, or explicitly
invoke the owned local worker once. It stops at the next approval/confirmation
boundary and never retries an uncertain charge. Exact qualification and
publication status are recorded in [progress](progress.md) and the containing PR.

The [workload-bound campaign](improvement-campaigns.md) is accepted in
[PR 74](https://github.com/CutbackAI/cutback/pull/74) after all 17 exact-head hosted
checks, installed and container recovery acceptance. It puts measured cache eligibility, native model/output
alternatives and conditional prompt search under one reserved campaign budget.
The [independent cache-first sample](../examples/improvement-campaign/README.md)
uses ordinary agent preparation, untouched confirmation, source checks and exact
rollback. The broader routing/retrieval/compression/training selection remains
unfinished; this does not imply launch or customer acceptance.

Working source adds [source-matched workload assessment](source-workload.md) and
an [independent committed application](../examples/source-workload/README.md).
It derives current source scope and models a separate trial's native-window
opportunity from retained authorized profiles. It makes no inference call or
source change. Acceptance and separate source-only follow-ups are in
[progress](progress.md); this is not unified cross-engine economic selection.

The source [native/cache portfolio](workload-native-portfolios.md) and complete
[independent walkthrough](../examples/workload-portfolio/README.md) are included
in accepted PR 74. The separate setup example can retain a committed synthetic
application and prepare a pending trial from observed source-window eligibility.
It grants no inference approval. Confirmation, source review and exact rollback
are separate steps, with cache-specific opportunity and unknown full-task costs.

## What the automatic workflow does

For qualified source and permitted examples, the agent can prepare source/data contracts, a frozen bounded search, candidate generation, validation and separately approved untouched confirmation. It can discover supported application checks, prepare independent base/proposed workspaces and an exact instruction/model/output-cap diff with rollback. An approved finite observation policy can compare later declared outcome windows and prepare a rollback review when they regress.

New source campaign preparations first validate a distinct static model/output-cap alternative. A passing alternative skips instruction generation; a failed one uses only already reserved prompt-search effort. An unchanged control skips the duplicate trial, and a static-only budget rejects failure rather than shrinking confirmation samples. Previously saved campaigns keep their version and approval. The dashboard and independent example show this stopping rule; [contract and acceptance](improvement-campaigns.md).

The independent [campaign application](../examples/improvement-campaign/README.md) exercises that path with synthetic native responses. Model support, source shapes, check commands and evidence coverage are explicit contracts. Unsupported dynamic source, unapproved content or unknown costs cause abstention; they do not become successful improvements. The workflow does not deploy changes.

## Engineering still required

1. **Gateway breadth and reliability:** the publicly merged source implements a separately enabled, finite text-gateway contract with virtual keys, shared budgets and no uncertain replay ([scope](gateway-budgets.md)); installed-package qualification and all ten hosted checks passed in [PR 33](https://github.com/CutbackAI/cutback/pull/33). The explicit HTTP SSE/first-text-timing extension and source/input-fidelity controls passed installed and all ten hosted gates in [PR 39](https://github.com/CutbackAI/cutback/pull/39). Additional providers/surfaces, configurable reliability/fallback behavior and operational acceptance remain unfinished.
2. **Broader automatic improvements:** evidence-driven selection across separate engines, remote/vector retrieval and learned reranking, tool/batch optimization, learned routing, learned/generative compression and additional source/framework adapters. [Bounded actual local corpus retrieval](retrieval-optimization.md) has its own accepted candidate/confirmation/settings-check journey in [PR 34](https://github.com/CutbackAI/cutback/pull/34). [Extractive context compression](context-compression.md) has its own source and qualification record. The new automatic native text portfolio covers model/output bounds and reserved instruction search; it does not silently authorize a different engine or establish a customer advantage.
3. **Broader evaluation:** generated criteria and real-data scenarios, qualified application/tool isolation and simulation, broader adversarial/guardrail integrations, and the documented modality/cloud specialties.
4. **Operational qualification:** evaluator/worker/gateway capacity, intended clean-host deployment and recovery modes, remaining collaboration/provisioning journeys, and their complete dashboard lifecycles.
5. **Release convergence:** make a separately versioned release containing the accepted source workflows, qualify its final archives and complete its publication gates. The QA artifacts used during development do not replace the published wheel.

These are implementation requirements, not requests for a maintainer to finish the engineering. They remain visible in the baseline until their user journeys and acceptance gates pass.

Accepted source also hardens [request bindings and proposed patch fidelity](source-request-safety.md): ambiguous Python scopes remain unresolved, and changing a shared model constant cannot silently change an unevaluated instruction/payload. This does not supply the remaining dynamic/shared-configuration source adapters.

The accepted source also adds [rendered native-input grouping](evaluation.md) before plan approval, provider dispatch and source review. Unused record fields cannot inflate the current dataset's independent example count; collisions across frozen splits reject. Cross-dataset rendered-request history remains unknown. The combined installed archives and all ten exact public CI gates passed in PR 39; namespace model references and explicit client-setting guards subsequently passed PR 40. These bounded increments do not qualify arbitrary dynamic application code.

## External evidence still required

Observed first-use trials must show that an unfamiliar developer can complete and explain the sample. Separately authorized application trials must test real task quality, complete cost attribution and later outcomes. A task-matched comparison must establish an advantage over the incumbent. Customer adoption, willingness to pay, production reliability and fundraising are not established by synthetic tests or feature count.

There is no additional account setup required to continue the current engineering. Paid provider calls, production deployment, customer outreach and customer claims require their own authorization. Private application source, identity and findings stay outside public examples, history and distribution archives.

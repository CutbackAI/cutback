# Model and context search

This independent support-policy application lets you follow one combined change: a smaller native model together with duplicate-line removal. It contains 24 invented policy questions and declared answer facts. The demo's model responses and usage are synthetic; they establish no customer quality, real savings or tokenizer accuracy.

From a source checkout with Docker, Git and the locked extras installed:

```console
cutback demo --joint-model-context
```

Choose **Explore sample → Compression**. Open the `synthetic-joint-model-context` confirmation in history. The demonstration has already frozen a model/context candidate grid, executed validation through the native SDK and PostgreSQL reservations, separately approved untouched-test confirmation and prepared a combined source diff. Model-only alternatives can fail the scripted quality criterion. Inspect the changed axes, component cost basis, quality gates and encrypted paired cases. Byte reduction alone cannot qualify a change. The sample makes no paid request.

To start your own review of this standalone application, copy this directory outside Cutback, initialize and commit a Git repository, then run:

```console
cutback workflow analyze APP_ROOT
cutback model-context inspect-producer APP_ROOT app.py --output inspection.json
```

The inspection output must be outside `APP_ROOT`. Detection and inspection parse source without importing it. Only this exact wrapper structure is qualified for automatic source changes; custom/dynamic builders require an inspected adapter. An SDK client supplied by another caller is outside this source qualification's destination and retry coverage.

With your explicitly chosen encrypted collector, project and permitted data rights, the agent can prepare the whole grid:

```console
cutback workflow prepare --target APP_ROOT --joint-context --example questions.jsonl --rights-basis synthetic --rights-reference owned-policy-facts --independent-labels --minimum 0.9 --min-test-samples 3 --assumed-usd-per-cpu-hour 0.01 --max-usd 1 --max-requests 200 --endpoint COLLECTOR --project PROJECT_UUID
```

This prepares an unapproved plan and makes no inference call. **On a real collector, continuing it uses the configured provider and can incur costs.** Review the exact plan and vendor/data/budget authority before using `workflow continue`; the synthetic demo is the zero-cost route. Follow `workflow status` for the exact hash, same-run reconciliation, selected candidate, separate confirmation and source proposal. Outputs remain in the application's ignored `.cutback` workspace.

For the dashboard authoring route, upload `inspection.json`, select the authorized dataset, check **Search model and output ceiling alongside context**, enter the CPU basis and minimum independent question count, then prepare. Read the frozen native request ceiling before approving. Independent confirmation needs a second exact approval.

For a collector proposal downloaded as `proposal.json`:

```console
cutback model-context patch APP_ROOT proposal.json --output change.json
```

Review both `change.patch` and `change.rollback.patch`. Apply only in your separate review checkout. Discover and run application checks on the exact base and proposed trees, then use `model-context review` with declared consumer coverage. `check_application.py` exercises the real wrapper with an owned in-memory response replacement. It is a consumer regression check, not model-quality evidence. The check runner requires explicit local execution; source review never publishes, deploys or alters live traffic.

Unknown native usage or CPU cost blocks joint economic selection. An uncertain native request stops the run with its reservation retained. No automatic billable retry, test-group reset or unconfirmed source patch is permitted.
